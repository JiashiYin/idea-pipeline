Glossary (each term once). **SFT** — supervised fine-tuning: training the model to reproduce recorded agent runs token by token.
**Sample** — the seed paper's training unit: a segment of a passing run between the points where the terminus-2 harness would
compress the context (sec. 3.5); 4,941 samples came from 1,272 runs, about $3.9$ per run. **Depth label $D$** — the smallest
stated turn cap under which one of two runs of a cheap model passes (sec. 3.1); **shallow** means $D \leq 3$, **deep** $D \geq 10$.
**Turn** — one agent reply plus the harness output; **$N$** the uncapped turn count, which the seed calls a model habit.
**Work $W$** — lines of the reference solution. **Matched count** — two training sets with the same number of samples;
**matched tokens** — the same number of assistant-loss tokens, the tokens that enter the SFT loss. **Arm** — one training set
in a comparison. **pass@1** — the share of tasks passed in one run, averaged over runs; **run spread** — its range over repeated
evaluation runs of one checkpoint. **Occupant** — a paper that already ran the claim's comparison. **Base model** — a pretrained
checkpoint before any post-training (Qwen3.5-*-Base); **Instruct** — the chat-tuned checkpoint.

## 4. Gates

**Gate 0 (premise hygiene) — three defects.** (i) The "field assumes" sentence was attributed to the seed, which never asserts
it: the paper's SFT claim is one arm against the base ("improves"), and its mechanism sentence is about segmented delivery, not
depth. The assumption is asserted by TerminalHorizon (quoted above) and by OpenThoughts-Agent ("longer episodes lead to higher
accuracy"), both with a measurement behind them. (ii) The matched quantity. A sample is a compaction-cut segment; a shallow run of
5–9 turns and 6.6–19.3 thousand end-of-run tokens (seed Table 1) is one sample, a deep run of 52.8 mean turns and 67.0 thousand
tokens is about 3.9. Matched count is therefore not matched supervision, and the community's standard is assistant-loss tokens
(RST, SWR, OT-Agent); RST states why in print. The probe's "third arm if longer by 1.5×" concedes the point but the headline is
written on count. (iii) "Released" tasks and samples: the dataset returns 401, the repository ships no SFT data, code or
hyperparameters, and the README defers both to the paper. The deep arm cannot be built or regenerated today (2026-11-15 lesson,
ninth occurrence of "code, curves and labels are not the transcripts").

**Gate 1 (cheap to kill) — fails today and is weak on paper.** Step 0 fails (defect iii); the probe's own clause parks it ("re-open
trigger: the paper's sample release"). On paper the 60 GPU-h budget is under a GPU-week, but the kill line cannot be read at 8B:
TMax Table 16 reports Qwen 3 8B on TB 2.1 as $1.1 \pm 0.9$, $6.0 \pm 1.4$ and $7.9 \pm 3.3$ (mean $\pm$ stderr over three runs), so
the per-run standard deviation is $\sigma = \mathrm{stderr}\sqrt{3} = 1.6$ to $5.7$ points. For two arms each averaged over
$r = 5$ runs the difference has standard error $\sigma\sqrt{2/r} = 0.63\,\sigma = 1.0$ to $3.6$ points; a two-point kill line is
$0.6$ to $2$ standard errors, a coin flip. The probe's uninformative clause (base five-run spread over two points on TB 2.1) fires
with near certainty: the expected range of five draws is about $2.3\,\sigma = 3.7$ to $13$ points. The binomial floor says the
same: at $p = 0.05$ on $n$ tasks one run has $\sigma = \sqrt{p(1-p)/n}$, 2.2 points for $n = 100$. The community has written this
regime down: 2607.17205 switches to held-out cross-entropy because "7B-scale models attain near-zero SWE-bench resolve rates".

**Gate 2 (Route A, a stated pressure point) — fails.** The pressure point was "the control nobody ran". Four papers in the window
ran it (sec. 2), on the same benchmarks, with the same teacher family (DeepSeek Flash/Pro, GLM) and bases from 4B to 35B. The
seed's omission is a revision item for its owners, not a strain visible in two source types. Read as Route B (a pre-registered
surprise), the expected cell has three matched comparisons against it on TB 2.x (RES +10.86, OT-Agent +3.8, WorkBorne +3.4) and
one within-task comparison for it (Terminal-Lego, 8B, $-0.8$), with OT-Agent's TBLite cell "within the per-benchmark noise" on the
claim's side — the 2026-11-08 lesson: count the published points on each side before filing. The field has not assumed; it has
measured, and the measured answer is "longer and deeper arms win on TB 2.x at 9B and above; at 8B the effect is inside the noise".

**Gate 3 (consumers) — one community, as graded; the action it would change is already its practice** (matched-token controls in
RST, SWR, OT-Agent; equal-count in RES, WorkBorne, GRADS).

**Gate 4 (mechanism and consequence) — holds in form, hollow in content.** The if_true action ("synthesis papers report a
matched-count shallow control") is what the synthesis papers do; the if_false action (depth is a training-data property at matched

**Gate 5 (durability) — as graded: one scale, one recipe.** Not reached.
