Glossary (each term once): **lesson / insight** — a short rule an agent writes for itself from one labelled past run. **Insights Only**
— WikiTrace's arm that gives the agent every insight in the task message with no source links (`--method kinj`). **Memory-induced
degradation** — WikiTrace's term: the agent fails a task it solves without memory. **Regression** — WikiTrace's metric, the share of
tasks No Memory solves that a memory method fails, $\Pr(M_{i,t} = 0 \mid B_i = 1)$ with $B_i$ the majority no-memory outcome over
three trials and $M_{i,t}$ the outcome with memory in trial $t$. **Rerun floor** — the Regression of three further no-memory trials
scored the same way. **Use-age** — the claim's clock: a lesson's retrieval count $u$. **Paired per-use harm** — the claim's quantity
$\hat\delta_{\ell u} = (c_{\ell u} - a_{\ell u})/n$: successes over $n$ runs with lesson $\ell$ withheld minus successes with it
retrieved, on the task of its $u$-th retrieval. **Frailty** — a per-lesson random effect $z_\ell$ (mean 1). **Crowding** — the
dependence of harm on the size of the store it is retrieved with, $|M_{\ell u}|^{\gamma}$. **Skill shadowing** — 2605.24050's term:
the agent selects a wrong unit more often as the library grows. **Oracle set** $\mathcal{S}^{\star}(q)$ — the skills that help task $q$
in isolation. **Library-induced pass-rate drop** — $\Delta(q, \mathcal{S}) = p(q, \mathcal{S}^{\star}(q)) - p(q, \mathcal{S})$, the
success rate with the helpful set alone minus the rate with the full library $\mathcal{S}$. **Inject / retrieve / traverse** —
WikiTrace's own three access modes (its Table 5): the whole memory in the prompt; a top-$k$ subset; the agent opens files.

## 3. The two closest papers' limitation text (verbatim, grep-verified)

**2611.14320 WikiTrace, Limitations (after sec. 6).** "Memory is built from binary trajectory outcomes, so a compilation's diagnosis
of a failure, and any insight drawn from it, may be wrong. A source link lets the agent check an insight against its run but does not
verify the insight. WikiTrace places every insight in the first message so that the agent never misses one, and the prompt therefore
grows with the memory. A memory too large to place in full would need the agent to find the insights it needs, a retrieval problem
this work leaves open. The causes of degradation (Section 3.2) and the descent labels (Section 5.2) come from an LLM judge that reads
the agent's reasoning, so they describe what that reasoning states, not what produced the outcome." **Sec. 4.1:** "In each trial,
every method builds its memory once from the same No Memory runs of the training tasks and is tested on the same test tasks. No method
may make additional runs to validate its memory." ... "The agent and memory builders use deepseek-v4-flash". **Sec. 3.3:** "The
compiler also extracts at most three insights per run." ... "we never update or delete them once written. The insight pool may
therefore contain redundant or conflicting insights, and deciding which one applies to the current task is left to the agent."
**App. C:** "A positive excess is added Gain, or, for Regression, added harm." **App. A:** "valid-unseen uses all 134 valid_unseen
games, set in four rooms absent from training" (the release's `configs/base.yaml` default is `test_size: 100`, which
`configs/alfworld.yaml` does not override; unresolved here).

**2605.24050 Skill Shadowing, sec. 5 Discussion.** "Our results point to skill shadowing as the primary bottleneck when scaling a skill
library: once semantically similar skills compete for selection, accuracy degrades regardless of the underlying model." ... "In
addition, our study covers $202$ skills on two models from a single provider, a scale at which context overhead remains modest. Whether
these patterns—and the mitigations above—hold as libraries grow by an order of magnitude or span diverse architectures remains an open
question." **Sec. 4:** "Within event o—where the agent selected correctly—the binary pass rate still falls as the library grows".

**Third, 2609.29144, sec. 8.** "The study covers inspectable scaffold edits with one frozen model and nine code-contract families. A
cumulative one-shot control for compounding, open-world and wrong-slot routing, additional editor/search backbones, and automatically
learned invariants remain future work." **Fourth, 2604.27003, Limitations:** "we focus on two environments with one representative task
pair each, one sparse retrieval backbone, and two runs per condition".

## 4. Why has this not been done

The per-lesson use-age curve is not done because the harnesses that inject every insight (WikiTrace, ExpeL's rule list, AWM) give
every unit the same retrieval count, and the harnesses that retrieve top-$k$ (ReasoningBank, MemCredit, UpliftMem) study the set, not
the unit's age. Its two ingredients are each in print: the fixed-unit, growing-store control (2605.24050, 2610.18522, 2609.29144) and
the per-memory counterfactual contrast on ALFWorld (2611.15600, 2026-11-11). The enabling piece the claim named — "WikiTrace's released
insights-only arm (2026-11-10)" — is not an enabling piece: it is a fixed-store protocol whose limitation section hands the retrieval
problem to someone else. The reason it is not done is also the reason it is not worth doing on this benchmark: ALFWorld's no-memory
rate is 94% and the whole store's regression is 2% of eligible tasks per trial, so a per-lesson curve has no headroom there.

## 5. Killing experiment check

The probe (C-W46-09, 28 GPU-hours, 8 days) assumed about four retrieved lessons per task, 8,000 episodes and 1,500 (lesson, use) pairs
on "WikiTrace's released insights-only store" with a local Qwen under vLLM. As released: (i) there is no retrieval, so the withhold-one
arm is one arm per injected insight — up to 150 insights ($50 \times 3$) per task, $150 \times 4 \times 134 \times 3 \approx 241{,}000$
episodes against the costed 8,000, a factor of 30; (ii) the actor is an API model through a Pi-to-OpenRouter relay (`llm.base_url`),
and one logged turn carries 52,444 prompt tokens, so an episode of about 25 turns is of order $10^{6}$ prompt tokens — a top-$k$ variant
at 8,000 episodes is $8 \times 10^{9}$ tokens, hundreds to a few thousand dollars at flash-tier prices, or a vLLM endpoint substitution
that the release does not document; (iii) the growing store (compile after every test task, top-$k$ retrieval, three passes, frozen
replay) is new harness work the limitation section explicitly leaves open — three to five days before the first episode. Re-costed:
about 60–80 GPU-hours plus a week of harness work for a quantity whose pooled value the source paper already bounds below the probe's
own kill line. Cost alone would park it; Gate 0 and Gate 2B kill it first. What survival would have required: a harness with top-$k$
retrieval and headroom (AppWorld at 72–75% or PlanCraft at 56% no-memory in WikiTrace's Table 1), the actor's temperature read from
the config (it is 0 — so $n = 1$ per arm up to serving noise), and a Gate 2B surprise that is not "shadowing grows with library size".

## 6. Verdict

**Killed (Gate 0, Gate 2B, Gate 4; both positions).** Gate 0: the named setup is not in the release (build-once, inject-all, API actor
at temperature 0), the use-age clock is degenerate on it, and the premise magnitude from the source paper's Table 6 (2% regression on
ALFWorld; added harm negative across suites) fires the probe's own first kill clause before any run. Gate 2B: the expected result is the
stated thesis of 2605.24050, 2610.18522, 2609.29144 and 2604.27003, and the alternative is WikiTrace's cause A and 2610.27406; the
field has both branches. Gate 4: the if_true action (a capacity or age bound) is Library Drift's shipped recipe. Gate 6 would fail
too: 1.8 papers a month on the store-size question, MemCredit on the estimator four days ago. Position does not rescue it: a lab with
WikiTrace's logs holds a fixed store in which every lesson has the same use count. **Residue (footnote, not a claim):** the per-lesson
withhold-one harm table on a growing top-$k$ store with headroom is an unmeasured curve; on the evidence (shadowing grows with size;
Scope-ORC's six-of-eight flip; MemCredit's sparse state-dependent credits) its expected reading is the field's, and it is a paragraph
in a paper about something else — a watch item with an automatic kill on the first paper that plots per-memory harm against store
size, which Q6's terms will find.

**Probe:** C-W46-09 — killed with the claim (setup absent from the release; kill clause fires at step 0 from the published table; cost
arithmetic off by a factor of 30 in the released configuration).
