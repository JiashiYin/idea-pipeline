**Terms, one gloss each.** *Hack auditor*: the release's name for the paper's "audit agent for robustness" — a Claude Opus 5.5
session that reads a simulation's code, runs it, and tries legal robot actions that break it. *Code policy*: a Python program
that reads privileged simulator state and emits ordinary robot commands (the paper's §6.3 device for generating demonstrations).
*CMA-ES*: a derivative-free evolutionary optimiser over a vector of real parameters. *Falsification*: the cyber-physical-systems
(CPS) testing practice of searching a simulator's inputs for a run that violates a formal specification; its budget unit is the
number of simulations. *Signal temporal logic (STL)*: a formal language for specifications over signals, with a real-valued
"robustness" that falsifiers minimise. *ARCH-COMP*: the annual CPS verification competition whose falsification track fixes the
benchmarks and the budget. *Playtesting / exploit discovery*: the game-testing community's words for an agent that finds
unintended high-scoring behaviour in a game build. *Physics-law oracle*: a test oracle that flags a simulator output violating a
conservation or consistency law (PhyFu's device). *Invalid success share*: $\epsilon = \#\{\text{success} \wedge
\text{violation}\} / \#\{\text{success}\}$; the claim's quantity is $\epsilon_{\mathrm{opt}} - \epsilon_{\mathrm{honest}}$.

## 0. Verdict in one paragraph

**Killed (Gate 1, with Gate 6 occupancy of the second clause); no residue above footnote grade.** Three things the parent
report took as premises are false in the release's own text. (i) The parent's mechanism gap — "search by execution and
score-climbing versus search by reading" — does not exist: the released hack auditor prompt says "Read the code, understand the
physics and controls, and decide which actions or sequences might expose problems. Actually run the environment and try them",
and the paper says each repair was "verified ... by replaying the audit's own reproduction". The audit is already a model-written
attacker with execution; the claim's third arm is the audit re-run with a budget cap, and the comparison that remains —
LLM-guided search with execution versus a numerical optimiser at a matched number of simulator calls — is a September 2026
result in the falsification community: LLM-Falsifier (2609.20752) beats the ARCH-COMP 2025 tools "based on a range of
optimization paradigms, from surrogate-based and Bayesian optimization to search-based testing, on 14 out of 21 specifications"
by simulations-to-counterexample, and names when the LLM loses ("benchmarks where this semantic connection is indirect, missing,
or less informative"). (ii) "The released code policy's parameters" is not a shipped object: the paper's code policies exist for
"two tasks in a gift box simulation with two FR3 arms" (§6.3), and the release's layout (`environments/<sim>/`: "physics, scene,
tasks, verifiers, renderer, REPORT.pdf"; `agents/`: evaluate, learning, harness, prompts, sim) lists no code policies, no
per-round `audit.md`, and no shared memory; what ships per simulation is the creator's `REPORT.pdf`. The condition "whose
three-round robustness audit recorded no remaining defect" is therefore not computable from the release, and the four code
policies for liquid, cloth and contact simulations would have to be written first. (iii) The two outcomes are not both
informative. A positive confirms what every owner states (the hack prompt: "If you did not find a failure, say that; it does not
establish that the environment cannot break"; the football report: "A finite run is evidence for its tested actions and
duration, not a universal guarantee that any adversarial joint sequence can never destabilize a numerical simulator") — Gate 2B,
as the parent already found. A null is a search-space artefact: 600 CMA-ES episodes over 10–40 waypoint, timing and force
parameters of one honest program search a sliver of the legal-command space that the hack auditor searches with arbitrary
programs, so "the optimiser found nothing" reads as "the parametrisation was too narrow", not "the audit was complete". A probe
whose negative teaches nothing fails Gate 1 by `standards.md`'s own sentence. The nearest communities also already hold the
"optimiser rediscovers what adversarial human testers found" result in the game register (RAID 2607.07498: six of the exploits an
RL population found "matched with exploits previously found by human playtesters") and the physics-law oracle under search for
engine bugs (PhyFu 2307.10818: "over 5K error-triggering inputs" across four engines). What is left for RoboWorld is a domain
transposition of LLM-Falsifier with PhyFu's oracle — a footnote in the Gym-Anything authors' appendix, not a claim. Same verdict
from the solo and the lab position. Of the three agent-built-simulator papers now in the theme (2610.40565, 2611.04974,
2604.06126 as the software parent), none audits its simulators with a numerical optimiser; RoboWorld's hack auditor is an executing
LLM, ARPG's check is "localized verification and correction" of MDP artefacts with RL training success as the metric, and
Gym-Anything's audit agent "verifies evidence for the environment setup against a quality checklist".

## 4. Why has this not been done, and why now

The matched-budget comparison of an LLM attacker with execution against numerical optimisers on a simulator was done in
September 2026 by the falsification community (2609.20752), whose benchmark culture (ARCH-COMP) already counts simulations as
the budget; the robotics corpus that would host the physics version shipped on 2026-10-29 with an executing LLM attacker
built in but without the code policies the probe parametrises or the audit reports it scores against. So "why not done" is: the
mechanism comparison is done elsewhere, and the corpus-specific version waits on artefacts that are not in the release and on
a group (the Gym-Anything authors) for whom it is one appendix row. Not "no reason found", but not an open question either.
Race window: adjacent register (optimiser-as-tester, falsification with LLMs, agent-built environments with audits) ran at about
0.4 papers per week over the last 52 weeks (Q2, Q3, Q7, Q14 in-window hits on the shape); the exact shape at 0 per week;
time to a first result 3–4 weeks (write four code policies, re-run the hack auditor, 100 GPU-h). Arithmetic passes, but the
result would be a service row.

## 5. Gate-by-gate verdict (position clause included)

- **Gate 0 (premise hygiene): fail on one premise.** "The released code policy" and "the audit report" are not released objects
  (§3). The quantity $\epsilon_{\mathrm{opt}}$ is well-conditioned (deterministic replay given seed and version, varied initial
  states shared by both arms), and the one-sentence trick exists.
- **Gate 1 (cheap to kill, both outcomes informative): fail — the failing gate.** Cost is under one GPU-week once the four code
  policies exist, but the null is uninformative by construction (a 10–40-parameter perturbation of one honest program versus the
  auditor's arbitrary legal-command programs), and the positive equals the owners' stated belief (§0, Gate 2B).
- **Gate 2 (pressure): route B fails** — the pre-registered surprise (the null) is a search-space artefact, and the positive is
  the field's assumption in the hack prompt's own sentence; no route-A pressure point names an optimiser audit for agent-built
  simulators (2609.09250 names "behavior under reward hacking" as a verifier validation in general).
- **Gate 3 (consumers): one community** (creation-audit pipeline builders; the Gym-Anything authors). Benchmark users and RL
  trainers would read it as a footnote.
- **Gate 4 (mechanism and consequence): pass as written**, but the consequence of a null ("three rounds suffice at this budget")
  is not licensed by the design.
- **Gate 5 (durability): weak** — tied to one release's 25 simulations and one parametrisation.
- **Gate 6 (ownership, density, timing): the second clause is occupied in mechanism** by 2609.20752 (domain-only difference, which
  `03_kill.md` does not count); the third-arm attacker is the release's own tool; the game register holds the
  optimiser-rediscovers-the-audit result (2607.07498). Density on the exact shape is 0; two pre-window precedents named (PhyFu
  2023, Bergdahl 2021; plus the parent's).
- **Position clause.** *Solo*: killed — public code, but the artefacts the probe names are not public, the null teaches nothing
  and the positive is stated knowledge. *Lab* (Gym-Anything or an engine team): killed as a claim — running `gar audit --auditor
  hack` beside a CMA-ES over a code policy at equal episodes is a one-week appendix row confirming or extending the loop (a
  service), and the re-open test is a question to the authors (whether any numerical optimiser has been run against a RoboWorld
  verifier), not a paper.

## 7. Lessons for `prompts/checklist.md`

- 2026-11-08 — A claim's description of a neighbour's mechanism ("the auditor is a reading model") is checked against the released
  prompt, not the paper's one-line summary: RoboWorld's `hack_prompt.md` says "Actually run the environment and try them", so the
  parent's "search by reading versus search by execution" gap never existed. Open the release's prompts before writing a
  mechanism contrast. (CL-W44-09.)
- 2026-11-08 — "Released X" in a probe names an artefact the README's layout section lists, or the probe is costed as if X must be
  built: RoboWorld's code policies exist for two gift-box tasks in the paper and nowhere in the release layout; per-round audit
  reports and the shared memory are run-time artefacts (`artifacts/audits/`), not shipped files; `REPORT.pdf` is the creator's
  report. Sixth occurrence of "code, curves and labels are not the transcripts". (CL-W44-09.)
- 2026-11-08 — "Matched budget" needs a matched search space: 600 episodes of CMA-ES over 10–40 parameters of one program versus
  an LLM writing arbitrary programs compares spaces, not search procedures, and the null is a search-space artefact. Pre-register
  the shared space before matching budgets; 2611.04838's "an exploit that was absent during the search" is the same lesson in
  print. (CL-W44-09.)
- 2026-11-08 — Two communities own "attacker A versus attacker B on a simulator": CPS falsification (role words: falsification,
  STL robustness, ARCH-COMP, "number of simulations", counterexample) owns LLM-with-execution versus numerical optimisers at matched
  budget (2609.20752); game testing (playtesting, exploit discovery, glitch, goalie AI) owns "the optimiser rediscovers what human
  adversarial testers found" (2607.07498, 2103.15819). Search both before any audit-versus-optimiser claim; the claim's own words
  ("agent-built simulator", "adversarial audit") returned only the corpus paper (Q9, Q15). (CL-W44-09.)
- 2026-11-08 — A protocol's own disclaimer sentence is a Gate 2B occupant: the hack prompt's "it does not establish that the
  environment cannot break" and the creator report's "not a universal guarantee that any adversarial joint sequence can never
  destabilize a numerical simulator" state the belief the probe's positive would confirm. Grep the released prompts and one
  shipped report for "guarantee", "establish", "sufficient" before writing a sufficiency surprise. (CL-W44-09.)
