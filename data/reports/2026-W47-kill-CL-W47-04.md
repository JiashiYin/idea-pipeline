Glossary (each term once). **Compaction** — replacing an agent's earlier context with a model-written summary when the window fills.
**Boundary $b$**, **$H_b$**, **$M_b$**, **remainder** — the cut index of a solved run, the history before it, the compacted context written
from it, the reference run's own actions after it. **Forward inventory** — CompAct-Bench's list of about 27.9 "required" units per
instance, written by a model from $H_b$ alone (App. G.1). **Live literal** — a string (path, URL, identifier, long number, quoted string)
from $H_b$ that a post-boundary action reuses before any post-boundary observation re-supplies it; compiler liveness (a value is live when
a later instruction reads it before it is overwritten) applied to a trajectory. **Live set $L_i$**, **live coverage $\kappa_{i\phi} = |L_i
\cap M_b| / |L_i|$** — instance $i$'s live literals, and the share of them appearing verbatim in compactor $\phi$'s $M_b$. **Sufficient
length $\ell^\star_i$** — the characters of the minimal line spans of $H_b$ containing every live literal; $\ell(\cdot)$ is character
length. **Dead unit** — an inventory unit carrying no live literal. **AUROC** — the probability that a scored success outranks a scored
failure. **Recurring detail** — Compact-Bench's term for a structured value occurring both before an artificial boundary and in the
session's next three to eight request payloads. **Supersession** — Contexture's rule that a later tool operation on the same target makes
the earlier observation a removal candidate; the compiler's dead store. **Recoverability axis** — 2608.16370's split of state into
externally queryable (D) and history-dependent (R). **Kept-rate gap $\Delta_\phi$** — compactor $\phi$'s kept rate on context-only live
literals minus its kept rate on environment-recoverable ones.

Restated, C-W47-08: extract $L_i$ from each released remainder, compute the dead-unit share of the forward inventory, $\ell^\star_i /

The one quantity computable at $0 on released data was computed, per the 2026-11-15 lesson. On Compact-Bench's `e2/sessions.jsonl` (146
sessions, 9,330 annotated recurring details, 8,770 of them found by substring in the JSON serialisation of the history; 2,417 also present
in the system prompt), with the body defined as the non-system messages flattened to text and $\ell^\star$ the summed length of the first
line carrying each detail:

$$\frac{\ell^\star}{\ell(H)}:\quad \text{median } 0.017,\quad \text{IQR } [0.010,\ 0.044],\quad \max 0.415;\qquad
\Pr\!\left[\ell^\star \le 0.10\,\ell(H)\right] = 0.897,\quad \Pr\!\left[\ell^\star \le 0.05\,\ell(H)\right] = 0.781,$$

with a median body of 259k characters and a median of 52 details per session; the details' own characters are a median 0.58% of the body.
Reading: the probe's expectation that $\ell^\star_i \le 0.10\,\ell(H_b)$ in "at least 85% of Coding instances" holds on this corpus by
arithmetic — a handful of paths and hashes with their lines is a few percent of any long history — while the lane's measured losses are
procedural and progress units (Case E: "procedural rather than factual"; Compact-Bench: "losing the progress needed to finish"). The clause
is true and teaches nothing about the binding constraint. The census also shows a design fact: 26% of the details sit in the system prompt,
which CompAct-Bench's "retained head" carries verbatim and Compact-Bench's extractor counts, so a live set must be defined net of the head.

If the traces ship, a redesign owes: (i) liveness as use before re-supply, not presence in future payloads, with both reported; (ii) the
